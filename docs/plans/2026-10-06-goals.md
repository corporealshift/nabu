# Goals: plan

Spec: `docs/specs/2026-10-06-goals-design.md`.

All of it is on one branch, `goal-surfaces`, as one PR, with a commit per step, so no
branch stacks on an unmerged one. Each step leaves `go build ./... && go vet ./... &&
go test ./...` green. The Android step also leaves `clients/android/gradlew.sh
testDebugUnitTest` green.

## Part 1: the surfaces go

### 1. Remove `/goal` and `--done-when`

- **Changes:**
  - `clients/go-tui/commands.go`: the `/goal` case, `actSetGoal`, `actClearGoal`, and the
    help line;
  - `clients/go-tui/tui.go`: the two action handlers;
  - the TUI tests that drive `/goal`;
  - `cmd/nabu/commands.go` and `cmd/nabu/main.go`: the `--done-when` flag, its
    `set_goal` call, and its usage line;
  - `docs/specs/2026-09-11-nabu-architecture-design.md` §10.3: a dated amendment saying
    the session goal is set only by the runner and the watcher.
- **Proves it:** the full gate passes, and `grep -rn set_goal clients/go-tui cmd/nabu`
  finds nothing.
- **Depends on:** nothing.

## Part 2: goals in the runner

### 2. Runs take a base branch and merge into it

- **Changes:** `clients/runs/`:
  - `state.go`: `Run.Goal` (the goal home's ID) and `StepMerge`;
  - `transition.go`: a goal run that passes `ci` goes to `merge`, and `merge` goes to
    `done`;
  - `runner.go`:
    - `setup` keeps a preset `Base`;
    - `pr` passes no label for a goal run;
    - `perform` handles `merge`;
  - `ports.go` and `exec.go`: `GH.MergePR` (`gh pr merge <n> --squash`). `CreatePR` and
    `EditPR` skip `--label` when the label is empty.
- **Proves it:** new rows in `transition_test.go`. A `runner_test.go` case for a run with
  `Goal` and `Base` set checks that it branches from `origin/<goal branch>`, opens its PR
  against that branch with no label, and merges it after green CI. An `exec_test.go` case
  checks the merge arguments.
- **Depends on:** nothing.

### 3. Goal state, prompts and parsers

- **Changes:** `clients/runs/`:
  - `goal.go`: `Goal`, `GoalStep`, `GoalBrief`, `Save` and `LoadGoals` in
    `<root>/runner/goals/`;
  - `goalprompts.go`: `BreakdownPrompt` and `CheckPrompt`;
  - `goalparse.go`: `ParseBreakdown` and `ParseCheck`;
  - `config.go`: `goal_rounds`, default 5.
- **Proves it:** parser tables cover a good answer, no block, bad JSON, an empty brief
  list, and unmet with no briefs. Prompt tests check the goal, the done-when list, the
  earlier rounds and the failure text all appear. There is a save/load round-trip, and a
  config default test.
- **Depends on:** nothing. No code calls it yet.

### 4. The goal step function

- **Changes:** `clients/runs/goaltransition.go`: `GoalTransition(Goal, GoalOutcome) Goal`
  and `ResumeGoal`. These are pure functions.
- **Proves it:** `goaltransition_test.go`, with one row per arrow in the spec's steps
  table: setup to breakdown; breakdown to runs; runs to the next brief, or to check when
  the round ends; a failed run to check; a second failure in a row to blocked; check met
  to pr; check unmet to a new round; the round cap; ci green to done; ci failing to check;
  a PR closed to blocked; Claude failing 3 times to blocked. Resume rows cover each kind
  of block, including a changed goal text.
- **Depends on:** 3.

### 5. The runner drives goals

- **Changes:** `clients/runs/`:
  - `runner.go`: `Advance` picks up `goal:requested` homes, resumes blocked goals, and
    advances each goal before the runs, so a run it creates moves in the same tick. A
    goal's runs are made directly as `Run`s with `Goal`, `Base` and a home created as a
    child of the goal home.
  - `goalrunner.go`: each goal step's actions. Setup pushes the goal branch. The goal
    syncs its worktree to `origin` before any write. It keeps the home's task list and
    `goal:*` labels, and builds the final PR's body.
  - `ports.go` and `daemon.go`: `Requested` takes the label; there are new `UpdateTasks`
    and `CreateHome(workspace, parent, description)`.
  - `exec.go`: `Git.SyncTo(dir, ref)`, a fetch then a hard reset to `origin/<ref>`.
- **Proves it:** `goalrunner_test.go` against the fakes:
  - a goal with two briefs runs both in order, the second branching from the goal branch
    after the first merged;
  - the check is met, and the final PR targets the default branch with the label;
  - the home's tasks and labels follow along;
  - a failed run goes to check and a replacement brief;
  - two failures in a row block the goal;
  - a restart in the middle of a round resumes it.
- **Depends on:** 2 and 4.

## Part 3: clients

### 6. TUI

- **Changes:** `clients/go-tui/`:
  - `commands.go`: `/goal <text>` sets the description, then `goal:requested`. A bare
    `/goal` on a blocked goal resumes it. Adds `goalLabels` and `goalStatus`.
  - `tui.go`: the action.
  - `view.go`: `groupByParent` nests to any depth, and a goal's status shows on its row.
- **Proves it:** table tests for `goalLabels`, `goalStatus` and three-level
  `groupByParent`. A command test checks `/goal` sends `set_option` (description, then
  labels) and never `set_goal`.
- **Depends on:** 1, which frees `/goal`.

### 7. Android

- **Changes:** `clients/android/`:
  - `ui/Runs.kt`: `goalLabels`, `goalStatus`, `parseGoal`, and `groupByParent` with a
    depth;
  - a Goal action and dialog in the session screen, mirroring Run, with the description
    pre-filled on a blocked goal;
  - `NabuViewModel.startGoal` and `SessionRepository.startGoal`;
  - the list's indent drawn from the depth.
- **Proves it:** unit tests for the helpers, and `startGoal` against the fake daemon
  (the description, then the labels, and never `set_goal` or `send_prompt`).
  `clients/android/gradlew.sh testDebugUnitTest assembleDebug` passes.
- **Depends on:** 5, for the labels' meaning.
