# Run page: plan

Spec: `docs/specs/2026-10-11-run-page-design.md`.

All of this is one branch, `run-page`, off main, merged as one PR with a commit per
step, so no branch is stacked on an unmerged one. It doesn't depend on #165 or #166.
`clients/runs/goalrunner.go` and `runner.go` are the only places likely to meet #166
when merging, and #166 doesn't touch them.

Each step leaves `gofmt -l .` empty and `go build ./... && go vet ./... && go test ./...`
green. Steps that touch the app also leave `clients/android/gradlew.sh
testDebugUnitTest` green. The Android projection test reads `protocol/vectors/`, which
is why step 1 changes the Kotlin projection as well as the Go one.

### 1. The `status` event and `rho.session.set_status`

- **Changes:**
  - `protocol/types.go`: `EventStatus` and `StatusData{Source, Kind, Data json.RawMessage}`,
    plus `StatusRun` and `StatusGoal`.
  - `protocol/validate.go`: `kind` is `run` or `goal`, `data` is a JSON object, and the
    encoded `data` is at most 64 KB (`MaxStatusBytes`).
  - `protocol/project.go`: `State.Status *StatusData`, the last `status` event, left out
    when there is none.
  - `protocol/assemble.go`: no code change. `status` is never assembled, and the vector
    pins that.
  - `protocol/spec.md`: the event in §3.1, the projection field in §5, the never-sent
    list in §6, and §7.27.
  - `protocol/schema/event.json` and `protocol/schema/jsonrpc.json`.
  - Vectors:
    - `validation/18-status.json`, valid;
    - `validation/19-status-kind-invalid.json`;
    - `validation/20-status-data-not-object.json`;
    - `projection/09-status.json`, where the last of two snapshots wins;
    - `assembly/07-status-is-never-sent-to-the-model.json`.
  - `daemon/api/handler.go`: `handleSetStatus`, which appends with `source: client`.
    Every `invalid_params` case is checked before anything is appended.
  - `clients/runs/daemon.go`: `Client.SetStatus`.
  - Android:
    - `protocol/Events.kt`: parse `status`, keeping `data` as a `JsonObject`;
    - `protocol/Projection.kt`: `status`.
- **Proves it:**
  - `go test ./protocol/...`: the vectors pass;
  - `daemon/api/handler_test.go`: `set_status` appends, it rejects a bad `kind`, a
    non-object and an oversized `data` with `invalid_params`, and it starts nothing on
    an idle session;
  - `ProjectionTest` passes against the new projection vector.
- **Depends on:** nothing.

### 2. `rho.session.stats {tree: true}`

- **Changes:**
  - `daemon/stats`: `Tree(root string, logs map[string][]protocol.Event) TreeStats`. It
    sums the way `window.go` sums sessions and adds `members: [{session_id, parent,
    labels, turns, working_seconds, tokens: {input, output}, started_at, last_event_at,
    archived}]`.
    Descendants are found through `parent`, at any depth.
  - `daemon/api/handler.go`: `handleSessionStats` reads `tree`. When it is set, it
    gathers the root and its descendants, archived sessions included, and calls
    `stats.Tree`.
  - `protocol/spec.md` §7.21.
  - `clients/goclient`: `StatsTree`.
- **Proves it:**
  - `daemon/stats/tree_test.go`, table-driven: a three-level tree's totals equal the
    sum of `stats.Of` over its members; a session outside the tree isn't counted; a
    member several levels down is found; the rows match each member's own numbers;
  - `handler_test.go`: an archived descendant is counted, and leaving out `tree`
    returns exactly what it returns today.
- **Depends on:** nothing. It can land before or after step 1.

### 3. The runner sets the status

- **Changes:** `clients/runs/`:
  - `state.go`:
    - `Run.Since`, set wherever the step or the task changes. That is in `Transition`'s
      callers in `runner.go`, so the transition stays pure.
    - `Run.Statused`, the last snapshot set, as `Goal.Tasked` is.
  - `goal.go`: `Goal.Since`, `Goal.Statused`, and `Verdict.At`, set where the goal
    runner records a verdict.
  - `status.go`, new:
    - `RunStatus(r Run, tasks []string, goalTitle string) ([]byte, error)` and
      `GoalStatus(g Goal, rounds int) ([]byte, error)`, building the spec's shapes;
    - `cutTo(s, 300)`;
    - the 64 KB trim: the oldest history rows go first, then the oldest verdict
      reasons.
  - `ports.go`: `SetStatus` on the `Daemon` interface. The test fakes record it.
  - `runner.go` and `goalrunner.go`: after each save, build the snapshot and set it
    when it differs from `Statused`. A failure is logged and never fails the run.
  - `testdata/status/run.json` and `testdata/status/goal.json`: the shared fixture,
    written by a test from recorded states. `-update` regenerates it.
- **Proves it:** `status_test.go`, table-driven:
  - a run's snapshot from a recorded state, with history, tasks, PR and goal;
  - a goal's snapshot with rounds, briefs and verdicts;
  - a long `why` is cut to 300 characters;
  - a run whose history would pass 64 KB loses its oldest rows and fits;
  - `Since` moves when the step moves and when the task moves, and not otherwise;
  - a second poll with nothing changed sets nothing;
  - a `SetStatus` error leaves the run moving;
  - the fixture matches what the builders produce.
- **Depends on:** step 1, for `SetStatus` and the 64 KB constant.

### 4. The app parses the status

- **Changes:** Android:
  - `protocol/Status.kt`: `RunStatus` and `GoalStatus` with kotlinx.serialization,
    unknown keys ignored, and a `parseStatus(kind, data)` that returns `Unsupported`
    for an unknown `version`.
  - `protocol/Stats.kt`: `TreeStats`.
  - `data/SessionRepository.kt`: `statsTree(client, sessionId)`.
- **Proves it:** `StatusTest.kt` decodes `clients/runs/testdata/status/*.json`, found
  the way `ProjectionTest` finds the vectors, and checks fields from both shapes.
  `version: 2` gives `Unsupported`.
- **Depends on:** steps 2 and 3.

### 5. The Run page and the Goal page

- **Changes:** Android `ui/`:
  - `RunPage.kt`: the derived values as plain functions, so they can be tested:
    - `timeline(status, tree)`: rows with duration, result and session;
    - `turnsPerTask(status, tree)`;
    - `header(status, now)`: the step line, with "42m in this step";
  - `RunPage.kt` and `GoalPage.kt`: the composables;
  - `GoalPage.kt`: `rounds(status)`, newest first, with each round's briefs and
    verdict;
  - `Screens.kt` and `MainActivity.kt`:
    - a home whose projection has a `status` opens on it;
    - a prompted home (`run:` label and a first prompt) gets the Run | Chat toggle;
    - the tree stats are fetched when the status changes, at most once a minute.
- **Proves it:**
  - `StatusPagesTest.kt`, using the shared fixture plus a hand-made tree. They check durations taken from consecutive `at`s, turns summed per task with
    retries counted, and rounds newest first;
  - `gradlew.sh assembleDebug` builds.
- **Depends on:** step 4.

### 6. Live

- **Changes:** none to code.
  - Install the daemon and runner built from the branch, between run steps. A restart
    mid-step makes the runner retry that step.
  - Install the app on Kyle's phone.
- **Proves it:**
  - `grep '"type":"status"'` finds a status event in the liftoff goal's home log and in
    the current run's home log, within one poll;
  - adb screenshots of:
    - the Goal page, showing round 7 and the earlier rounds' verdicts;
    - the Run page, showing the live step card, a timeline that includes plan-review
      and verify-review, and turns per task;
  - tapping a timeline row opens the step session;
  - screenshots and numbers go in the PR.
- **Depends on:** steps 1 to 5.

## Not doing

- The TUI.
- Backfilling status for runs or goals that finished before this ships.
- Cost, or anything priced.
- Notifications driven by status. The phone's notifications are unchanged.
